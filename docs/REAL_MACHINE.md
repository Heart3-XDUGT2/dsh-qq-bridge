## 一、他做的那两步(记录,已完成)

| # | 做什么 | 为什么 |

| 1 | **把 AstrBot 那条反向 WS 关掉**(最干净:整个退出 AstrBot) | `6199` 现在归它(见上表)。它不放手,我们就听不上 |

**为什么建议整退出 AstrBot(而不是只停某一侧)**:桥的 2 秒轮询就跑在 AstrBot 里面 —— 停一半它可能
还留着半张嘴。**端口本身就是互斥的**(一个进程才能听 6199,NapCat 也只跟听着的那个说话),
所以我们抢不到端口时既不会发重、也不会发漏(`canSend` 挡着,不去取行)。想确认它真的松手了:

```powershell
Get-NetTCPConnection -LocalPort 6199 -State Listen | Select-Object OwningProcess
```

没有输出 = 没人听了,这时我们最多 15 秒就自己接上。

**顺序反过来也行**(先重启、后关 AstrBot):我们起不来时**不认命** —— 每 15s 重试一次、最多 5 分钟
(`lib/index.js` 的 `echo-qq.listen()`),他一腾出端口我们自己就接上了。
过渡期**不丢话、也不双发**,而且**不抢主包老路的活儿**:叫醒来了但还没接上时,我们**不去取行**
(取来也发不出去,只会白占 30s 租约),行留在主包的出站队列里让另一条路照旧送。
**NapCat 那边一个字都不用改** —— 它早就指着 `ws://host.docker.internal:6199/ws` + 那个口令,谁听 6199 它就跟谁走。

配置在 `~/.dsh/echo-qq/config.json`(数据在数据目录,与源码目录分开)。改**配置**不用重启。
**两条"空 = 拒收"**记牢:`accessToken` 空 = 拒收一切连接;`allowedUsers` 空 = 一律拒收
(绝不"空即全通")。这两条体检里都是**挡路项**。

## 三、`fail` 与 `warn` 的口径(为什么这么分)

- **`fail` = 这条不通就根本收不到/送不出**:口令空、白名单空、两条路都不通(`mode: none`)、
  总闸开着却没注册上、有连接被口令拒、主包的门关着。
- **`warn` = 能用但有代价**:走的是 HTTP 轮询兜底(不是零轮询)、NapCat 还没连上、心跳 stale、
  还没有出站样本、有行没送出去、配置有坏值。**总闸关着算 warn 不算 fail** ——
  "装上 ≠ 开了",那是待办不是故障。

## 四、真机这一轮要盯的事

1. 他手机上给**小号**发一条私聊 → 她**收得到**(体检里 `received` 涨,主包那边多一条渠道);
2. 她回话 → **真的到他手机**(体检里 `sent` 涨,分段耗时有样本);
3. **分泡/节奏/打断**照旧(几泡之间仍有间隔,不是一次性刷过来);
4. **DSH 窗口里说的话不许自动发到 QQ**(`held` 语义);
5. 白名单外的号发消息 → **一律拒收**(体检里 `rejected` 会涨,日志里有"入站被拒");
6. 群聊消息 → 一律不收(个人机器人,自 v0.29.0);
7. 把 NapCat 关掉 → 心跳转 `stale`、体检**如实报出来**(不装死、不伪造);
8. 卸载插件 → 门关回去(她没嘴了),主包那边 `hasChannel()` 回到关。
